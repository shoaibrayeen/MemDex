1.0.0-beta

beta release 19 September 2026

First working version: discovery, deterministic optimization, a small generated index, local embeddings, a local ChromaDB store, semantic search, backups, an activity log and an optional LLM layer.

Core pipeline

  • addMemory discovery limited to configured sources Reads only MEMORY.md, memory/, .memory/ and the assistant directories listed in config. A README is documentation, not memory, so a repository-wide markdown sweep was deliberately not implemented.
  • addFence-aware markdown parsing Headings inside fenced code blocks never split a memory, and a leading --- is only frontmatter when a closing delimiter exists — otherwise it is a horizontal rule.
  • addSplitting at heading boundaries only Sections split down to their leaves so retrieval returns one topic rather than a whole chapter. Sections below min_unit_tokens fold back into their parent, heading and all, so nothing is lost. A paragraph is never cut in half.
  • addDeduplication, exact and near Exact matches on normalized text, near matches via a word-overlap prefilter confirmed by sequence similarity. Code fences keep their exact text, so two snippets differing only in a variable never merge.
  • addConservative compression Removes conversational filler, collapses blank-line runs and drops verbatim repeated paragraphs — nothing else. It never paraphrases, never reflows and never touches the inside of a fence.
  • addStable memory IDs A four-rung adoption ladder — frontmatter ID, content hash, title plus category, then a fresh ID — so mem_a8f31c survives a move, a rename or an edit.
  • addPlan and apply split build_plan computes the whole result without writing anything or opening the vector store; apply_plan performs every side effect. This is what makes --dry-run a real preview rather than a best effort.

Storage and retrieval

  • addEmbedded local ChromaDB Persistent client at .memdex/chroma, cosine space, telemetry off, no server process. All Chroma calls are confined to store.py.
  • addThree embedding providers local (bundled MiniLM ONNX, one download then offline), hash (pure standard library, works air-gapped) and ollama. A failure in any of them falls back to hash with a warning rather than failing the run.
  • addSemantic search memdex search with --top-k and --category, scored as 1 − cosine distance.
  • addActivity log in its own collection Every applying command records one row. It survives memdex clean on purpose — wiping the database is itself an event worth remembering — and only clean --all removes it.

Commands and interface

  • addTwelve commands init, run, search, compact, index, bootstrap, status, history, ui, doctor, restore, clean.
  • addCoding-project validation and monorepo prompt init refuses to set up in a folder that is not a code project, and asks whether a subdirectory user meant the repository root. Other commands walk up to find .memdex/, the way git does.
  • addBootstrap for projects with no memory Reads a token-budgeted slice of the repository and asks a high-context LLM for seed memories, which run then maintains like any others.
  • addBackups, restore and dry runs Every applying command copies what it will touch to .memdex/backups/<timestamp>/ with a manifest. Restore is itself reversible.
  • addLocal dashboard, and its terminal twin A read-only page on 127.0.0.1 built on the standard library — no CDN, no build step. memdex history and memdex status show the same data in the terminal, and setup.sh --no-ui installs without it.
  • addOne-shot setup.sh Installs uv if needed, installs the CLI, verifies it and prints a quickstart. --dev also runs the tests and the linter.

Packaging and providers

  • addAssistant-driven bootstrap (no LLM needed) With no memory and no LLM configured, memdex run and memdex bootstrap seed a MEMORY.md template addressed to the coding assistant already working in the repo: fill the sections, run memdex run. Template instructions live in HTML comments and unfilled placeholders in a fixed marker — both are stripped at indexing time, so scaffolding never becomes memory.
  • addmemdex refresh — memory follows the code Compares the working tree against the last refresh's git baseline (pulled commits and local edits alike), flags memories that cite changed or deleted files, and with --llm lets the model keep/update/mark-outdated each one — updates apply only to Memdex-generated files, after a backup. Ends with a re-index so pulled memory edits are re-embedded. Built for repositories several teams commit to.
  • addDocker image and compose file A slim image whose entrypoint is the CLI; the target project mounts at /workspace, a named volume keeps the one-time embedding-model download, and the dashboard runs with ui --host 0.0.0.0. Nothing project-specific is baked in.
  • addOpenAI as an LLM provider provider: openai presets the base URL and reads the key from $OPENAI_API_KEY (or the variable named by api_key_env) at call time. A key pasted into config.yaml is rejected at load, and errors never echo it.
  • addRemote-endpoint warning When the configured LLM endpoint is not local, every LLM command says so before sending anything: leaving the machine is the user's call, never a surprise.
  • addmemdex ui --host The dashboard binds 127.0.0.1 by default; Docker users bind 0.0.0.0 (the page is read-only) so the host can reach it. A non-loopback bind prints a notice.
  • addRoot CLAUDE.md as a default readonly source Claude Code keeps its primary project rules there, so it is indexed and searchable alongside AGENTS.md and the assistant directories — never rewritten.

Fixed during development

Found by running Memdex against its own repository and the bundled example.

  • fixCategory keywords matched inside unrelated words Substring matching meant ci matched inside “decisions” and “sequencing”, filing architecture decisions under development. Keywords now match on word boundaries, with an optional trailing “s” so a ## Projects heading still counts as project.
  • fixToken savings measured the wrong thing Counting bytes on disk showed memory getting larger, because the index is new text. Context cost (everything loaded before, the index alone after) and content size are now reported as two separate, clearly labelled numbers.
  • fixA document's title polluted every breadcrumb A file opening with # Project Memory made “project” a feature of every memory in it. A sole top-level heading that reads like a document title is now unwrapped; a sole # Architecture, which really is context for what follows, is kept.
  • fixDescriptions cut at line wraps and mangled identifiers The first line was being used instead of the first sentence, and the emphasis stripper turned tenant_id into tenantid. Descriptions now read a whole paragraph, and only paired emphasis markers are removed.
  • fixTitles were left out of the vector “how do I run the tests” ranked a naming convention that merely mentioned _test.go above the actual Testing memory. The title and breadcrumb are now embedded with the body, which fixed that query and improved every other one measured.
  • fixReadonly files produced one index line per section Five entries all pointing at .claude/CLAUDE.md gave a reader no way to find the right part of a file Memdex cannot split. The index now lists each readonly file once, under its own title; search still returns individual sections.
  • fixCode-only memories had blank descriptions A section that is nothing but commands now describes itself with its first command instead of an empty index line.
  • fixCompact detail lines printed under the wrong heading Obsolete memories were listed beneath “Similar, kept apart”. Each finding now prints its own details directly under its own heading.
  • fixmemdex index could have deleted the memory tree Index mode plans no memory files, so the diff concluded every existing one was obsolete. It now runs in an index-only mode that cannot produce a delete.

Known limitations

  • noteMoving, retitling and rewriting at once loses an ID All three adoption signals change together, so the memory is treated as new.
  • noteThe default embedder is not covered by tests The suite is offline by design, so it exercises the hash provider. The local path is verified by hand after changes to embed/ or store.py.
  • noteLLM mode can rename memories between runs A renamed memory moves file, so --llm runs are not byte-identical the way deterministic runs are.
  • noteSetext headings are not recognized Only ATX headings (# … ######) mark a boundary.
